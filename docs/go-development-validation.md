# Проверка Go Development 0.3.0

Переименование cohesive-development в go-development с сохранением локальной
основы 0.2.0 (в main была 0.1.0). Добавлены Go-дизайн/данные, concurrency,
тестирование/profiling, lifecycle. Основной файл — 125 строк; справки условные.

## Проверки

- Skill creator quick_validate: PASS.
- Repository structure и Markdown links: PASS.
- Unittest инфраструктуры репозитория: 96 PASS; это не оценка качества решений модели.
- git diff --check: PASS.
- Metadata, default prompt, README и AGENTS fragment используют новое имя.
- В переносимом навыке нет локальных абсолютных путей, приватных адресов проекта,
  raw PDF, извлечённого текста книги, credentials или журналов.

На Go 1.26.2 darwin/arm64 в изолированных временных файлах выполнены четыре
проверки через go test -race -count=1 -timeout=30s, все PASS:

1. Typed nil отличается от nil interface; чтение/len/delete nil map допустимы.
2. Ограничение capacity slice не устраняет aliasing существующих элементов.
3. Unbuffered send завершается до окончания дальнейшей работы receiver.
4. Раздельные mutex-секции чтения/записи дают lost update без data race;
   одна критическая секция сохраняет оба инкремента.

Отрицательный compile-контроль generic union двух struct types с общим ID
отвергнут компилятором: v.ID undefined. Это реальная проверка расхождения с
предварительным примером generics из книги, не запрет generics вообще.

## Самопроверка решений

Desk-check автора, не независимый модельный прогон или человеческий эксперимент:

| Ситуация | Проверяемый критерий |
|---|---|
| Локальная правка parser | Нет обязательного аудита всего приложения или Kubernetes |
| Только review | Находки без записи |
| Широкий refactor | Полная карта покрытия; остаток не скрыт |
| Один production adapter | Интерфейс допустим по конкретной потребности caller |
| Generic Repository | Требуется общий алгоритм, не сходство полей |
| Timeout при I/O | Payload/reservation не освобождается до конца использования |
| Зелёный race test | Проверять логические инварианты отдельно |
| Увеличение buffer | Нужны бюджет и сопоставимые измерения |
| Kubernetes из-за Ardan | Не расширять задачу; runtime scope задаётся отдельно |
| Соседний WIP | Проверить SHA/владельца, не перезаписывать чужую работу |
| Несвязанный текст/инфраструктура | Навык не запускает Go-аудит |

## Пределы

Охвачены объяснения всех глав книги, листинги изучались выборочно; все примеры
не исполнялись и постраничная визуальная проверка не заявляется. Узкие Go-проверки
подтверждают semantics, а не эффективность навыка. Исторические модельные пилоты
описаны отдельно и не доказывают человеческую читаемость новой версии.

Новые hooks, профили агентов и разрешения не добавлены. Исторический отчёт 0.1.0
сохранён. Установка и публикация проверяются отдельно. Draft PR исключает включение
репозиторного owner auto-merge; merge/release не входят в поручение.

## Обновление 0.5.0 — 2026-11-10

Основа 0.4.3 сохранена. Сравнение с четырьмя внешними наборами дало точечные
дополнения в существующие справочники: context/группы, владение каналами, тестовые

Матрица принятого и отклонённого с ревизиями источников находится в
[evidence.md](../skills/go-development/references/evidence.md#go-development-050-внешние-навыки-как-дополнения).

Фактически выполнены quick_validate, repository structure, local links и
git diff --check — PASS. Существующие 96 unittest инфраструктуры — PASS;
они проверяют инструменты репозитория, не эффективность Go-инструкций.
Просмотрен весь diff на приватные пути, данные и непредусмотренное расширение прав.

Самопроверка по положительным и отрицательным сценариям:

| Сценарий | Решение кандидата относительно основы |
|---|---|
| Передача `*Job` с исключительным ownership | Допустима; запрет внешнего набора не перенесён |
| Struct copy со slice и дальнейшая мутация отправителем | Сохранён запрет считать shallow copy изоляцией |
| Coordinated close после всех producers | Допустим; проверка отсутствия будущих sends |
| Запрос после успешного errgroup.Wait | Добавлено предупреждение об отменённом group context |
| Detached request continuation | Добавлены собственный бюджет и shutdown owner, без обещания durable delivery |
| Fixture для parallel subtests | Уточнены Cleanup и порядок cancel/join/Close |
| Повторная доставка после singleflight | Отдельный контракт dedup; группа его не обеспечивает |
| Маленький parser refactor, старый toolchain | Сохранены объём и версия; нет обязательных 80%, profiling или модернизации |

Это desk-check автора по тексту и первичной документации, не независимый модельный
прогон. Новые Go-листинги не добавлялись; runtime-эксперимент и измерение улучшения
ответов модели не выполнялись. Не добавлены новые зависимости навыка, hooks,
агенты, автозапуски или полномочия. Публикация этой ревизии — отдельный draft PR;
исторические проверки 0.3.0 выше не выдаются за повторно выполненные эксперименты.
